# Crypto Match-3 — Telegram Mini App

Игра «три в ряд» для Telegram. Бесплатные попытки ограничены энергией
(реген +1/час до максимума), за TON можно докупить попытки и бонусы.

## Что уже готово (этап 1 — сама игра)

Полностью рабочий фронтенд Mini App: `webapp/`

```
webapp/
├── index.html          экраны: меню / игра / нет энергии / конец / магазин
├── css/style.css       вид поля, фишек, анимации, тема под Telegram
└── js/
    ├── config.js       ВСЕ настройки: поле, баланс, энергия, пакеты TON
    ├── energy.js       попытки + реген по времени (localStorage)
    ├── game.js         движок match-3: свапы, матчи, гравитация, каскады
    └── main.js         UI, таймеры, Telegram WebApp SDK, магазин (заглушка)
```

Геймплей: поле 9×9, 5 фигур (квадрат, круг, треугольник, звезда, ромб),
25 ходов на попытку, очки за совпадения 3+ с множителем за каскады.
Управление: тап-тап по соседним или свайп. Если игрок бездействует
(по умолчанию 5 c — `game.hintDelayMs`), подсвечивается возможный ход.
Если ходов не осталось вовсе — поле автоматически перемешивается.

**Спец-фишки (плюшки).** На обычной фишке с небольшим шансом появляется
значок; награда выдаётся, когда фишка попадает в матч:

| Значок | Награда | Шанс |
|--------|---------|------|
| 🪙 Монеты | внутренняя валюта (копится) | 5% |
| 🎁 Бонус  | случайная награда | 2% |
| 💥 Бомба  | взрывает 8 соседей (большой каскад) | 2% |
| ⚡ Энергия | +1 попытка | 1% |

Настройки спец-фишек — в `config.js` → `specials.items` (иконка, шанс,
награда). Эмодзи-значки корректно рисуются на телефонах и в Telegram
(в headless-превью часть может показываться квадратом — это шрифт, не баг).

### Запуск локально

```bash
cd webapp
python -m http.server 5577
# открыть http://localhost:5577
```

## Что меняется в config.js

| Параметр                | Значение           |
|-------------------------|--------------------|
| `energy.max`            | максимум попыток (5)|
| `energy.regenMs`        | время на +1 попытку (1 час)|
| `game.movesPerGame`     | ходов на игру (25) |
| `board.cols/rows/types` | размер поля и число фишек |
| `ton.packages`          | пакеты покупки за TON |
| `ton.receiver`          | адрес-кошелёк получателя |

## Роадмап

**Этап 2 — бот и бэкенд.** Telegram-бот (кнопка запуска Mini App), сервер
с БД (пользователи, энергия, история). Логику энергии из `energy.js`
переносим на сервер — иначе попытки накручиваются через DevTools. Клиент
будет только отображать значения, проверенные через Telegram `initData`.

**Этап 3 — оплата TON.** Подключаем TON Connect (`buyPackage` в `main.js`
уже помечен `TODO`): кошелёк отправляет сумму на `ton.receiver` с
комментарием = `userId+пакет`; бэкенд ловит входящую транзакцию (через
TON API / индексатор) и начисляет энергию. Сейчас покупка работает в
демо-режиме (мгновенное начисление без оплаты) для проверки механики.

**Этап 4 — плюшки.** Бустеры (бомба, перемешать), x2 очки, ежедневные
награды, таблица лидеров, реферальная программа.

## Деплой на VPS

**Docker (рекомендуется):**

```bash
cp server/.env.example server/.env    # заполни BOT_TOKEN, WEBAPP_URL, CORS_ORIGIN, TON_RECEIVER
docker compose up -d --build
docker logs -f m3
```

**Без Docker (systemd):** см. заголовок `server/m3.service` — там пошагово.

**HTTPS обязателен** (Telegram Mini App требует https). Простейший путь —
Nginx reverse-proxy на `127.0.0.1:3000` + Let's Encrypt (`certbot`).

Health-check: `GET /health` → `{ok, driver, uptime}`. Docker HEALTHCHECK
и любые uptime-мониторы (UptimeRobot, Better Stack) можно натравить.

Подробности по безопасности и антифроду — `SECURITY.md`.
