# Backend — серверная энергия

Сервер хранит попытки/монеты/рекорд в базе и проверяет их сам. Клиент
их только отображает и не может подделать (как было с `localStorage`).

## Что внутри

```
server/
├── server.js     Express: раздаёт фронтенд + API
├── telegram.js   проверка подписи Telegram initData (HMAC)
├── energy.js     серверная логика энергии (реген, списание, начисление)
├── db.js         роутер БД: JSON (dev) или SQLite (prod)
├── db-sqlite.js  SQLite-адаптер (WAL, атомарные записи)
├── migrate-to-sqlite.js  однократная миграция data.json → data.sqlite
├── config.js     настройки (энергия, лимиты, токен)
└── .env.example  пример переменных окружения
```

## API

Каждый запрос несёт `initData` (от Telegram) — по нему сервер узнаёт игрока.

| Метод | Что делает |
|-------|-----------|
| `POST /api/state` | текущее состояние: энергия (с регеном), монеты, рекорд, таймер |
| `POST /api/play`  | списать 1 попытку (или `409 no_energy`) |
| `POST /api/end`   | записать результат игры и награды (с антифрод-лимитами) |

## Запуск локально

Нужен Node.js 18+.

```bash
cd server
cp .env.example .env      # (Windows: copy .env.example .env)
npm install
npm start
# открыть http://localhost:3000
```

Без `BOT_TOKEN` сервер стартует в **DEV-режиме**: подпись Telegram не
проверяется, игрок определяется по `devUserId` (только для отладки!).

## Деплой на сервер (VPS)

1. Создай бота у **@BotFather**, получи `BOT_TOKEN`.
2. Залей проект на сервер, в `server/.env` пропиши `BOT_TOKEN` и `PORT`.
3. `npm install` и запуск под менеджером процессов:
   ```bash
   npm install -g pm2
   pm2 start server.js --name match3
   pm2 save
   ```
4. Поставь домен + HTTPS (Telegram Mini App требует https). Проще всего
   через **Nginx** (reverse-proxy на `localhost:3000`) + бесплатный
   сертификат **Let's Encrypt (certbot)**.
5. В @BotFather задай ссылку на Mini App: твой `https://домен`.

## Переезд на SQLite (рекомендуется в проде)

По умолчанию сервер пишет в `data.json` — просто, но при аварии SIGKILL
можно потерять последние ~1с записей и файл может побиться при
одновременных записях. Для прода переключись на SQLite:

```bash
cd server
npm install                        # подтянет better-sqlite3 (optional dep)
node migrate-to-sqlite.js          # data.json → data.sqlite (один раз)
# затем в .env:
#   USE_SQLITE=1
pm2 restart match3
```

SQLite использует WAL-журнал: устойчив к падению процесса, атомарные
записи, поддержка индексов. Файл `data.sqlite` бэкапится тем же
скриптом (`server/backups/`).

## Антифрод

- Энергия списывается и регенерируется **только на сервере** — клиент не
  хранит её и не может накрутить.
- `initData` подписан Telegram; сервер проверяет подпись и свежесть —
  подставной запрос не пройдёт.
- Награды за игру клиент считает сам, поэтому сервер **обрезает** их
  лимитами (`config.js → caps`): максимум монет/энергии за одну игру.
  Полную защиту (пересчёт игры на сервере) добавим при необходимости.

## Дальше (этап 3 — оплата TON)

Добавить `POST /api/ton/...`: сервер следит за входящими транзакциями на
кошелёк-получатель (через TON API) и начисляет попытки тому игроку, чей
`userId` указан в комментарии платежа. Начисление — всегда на сервере.
